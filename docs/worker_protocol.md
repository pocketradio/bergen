# Worker protocol contract

This document defines the worker-specific portion of the Phase 1.5 contract package. Shared lifecycle, ownership, storage-version, idempotency, error, and retry rules are authoritative in [contracts.md](contracts.md).

All endpoints require TLS outside local development and an authenticated worker credential (separate from client JWTs). The API derives worker identity from that credential, never from a request field. All JSON is versioned by `/v1`. Identifiers and object keys are opaque; never accept arbitrary FFmpeg flags. The Go representations live in `internal/protocol` and use domain types from `internal/domain`.

- `POST /v1/worker/poll` with `{ "capabilities": { "video_codec": "h264", "audio_codec": "aac" } }`. Returns `204` if no eligible work, otherwise `200` with a task ID, attempt ID, lease expiry, short-lived scoped input/output URLs, and the server-defined immutable profile. The profile contains its ID/version, container, codecs, dimensions, pixel format, frame-rate/VFR allowance, H.264 profile/level, video bitrate, and audio sample rate/channels/bitrate. Claim and attempt creation must be one DB transaction.
- `POST /v1/worker/heartbeat` with `{ "attempt_id": "..." }`. Returns `200` with `{ "lease_expires_at": "RFC3339" }` only for the authenticated worker's current, unexpired `leased` attempt; it returns `409` with `stale_attempt` or `lease_expired` otherwise. No worker-supplied timestamps or lease duration are accepted.
- `POST /v1/worker/submit` requires the `Idempotency-Key` header and accepts `{ "attempt_id": "...", "object_key": "...", "size": 123, "sha256": "64-character hexadecimal checksum" }`. Returns `202` with `{ "result_id": "...", "state": "submitted|validating" }` for a current attempt awaiting coordinator validation. The submitted key must be opaque and exactly match the server-assigned output key. An identical replay returns the stored submission; a different payload for the same worker/attempt returns `409 conflict`. Submission relinquishes worker lease renewal and creates a coordinator-owned bounded validation lease. Upload alone never awards credits.

Errors use `{ "code": "stale_attempt", "message": "..." }` without leaking credentials or presigned URLs. Exact lease, retry, size, and policy parameters remain open decisions in `docs/decisions.md`. Endpoint handlers, authentication, leases, and persistence are implemented in later phases.
